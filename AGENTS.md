# AGENTS.md

This is the operating contract for any coding agent working in this repository (Claude Code, Copilot, Codex, and others).
The repo is **public**. It builds https://mickosis.github.io, the resume and profile site of Miguel Carlo Rigunay, plus a downloadable PDF resume.

## What this repo is

- **Astro + TypeScript** static site. No UI framework runtime.
- **One source of truth:** `data/resume.yaml` (JSON Resume schema written as YAML, with custom `x-` keys). The site (`src/pages/index.astro`), the PDF (`src/pages/print.astro` rendered to `dist/resume.pdf`) and the README all read from it.
- **Project stats** come from `data/github.json`, generated by `scripts/fetch-github.ts` every week in CI. Never hand-edit it.
- **Which repos appear** is set in `data/repos.yaml`.
- **Theme** follows the owner's Ghostty terminal: Dark+ palette, Hack font, glass title bar. The light theme is VS Code Light+. Tokens live in `src/styles/terminal.css`.

## Hard rules

1. **Never publish a phone number.** It must not appear in YAML, HTML, the PDF or git history. The schema rejects `basics.phone`.
2. **Never name a private repository.** Private repos appear only as masked cards keyed by a public alias in `data/repos.yaml`. The alias-to-repo mapping exists only in the `PRIVATE_REPOS` secret. Don't write private repo names, URLs, commit messages or README text into any file here. When describing a private project, stay generic about what it does and how.
3. **Don't hand-edit generated files:** `data/github.json`, `dist/`, `tests/__screenshots__/linux/` (CI owns these).
4. **Keep the PDF at 2 pages or fewer.** `scripts/build-pdf.ts` and `tests/pdf.spec.ts` enforce this. If content grows, trim older roles or the print layout rather than shrinking fonts below 9pt.
5. **Copy style:** active voice, plain verbs, sentence case, no filler. Quantify results where the source gives a number. Never invent metrics, employers, dates or certificates. Ask when a fact is missing.
6. **LinkedIn is authoritative** for titles, company names, dates and locations when it conflicts with an older CV.

## Quality gates (all must pass before a merge or deploy)

```bash
npm run build          # astro build + render dist/resume.pdf (fails above 2 pages)
npm test               # Playwright: e2e + visual on desktop, iPhone 13 (WebKit), Pixel 7
npm run leak-check     # needs PRIVATE_REPOS in env; fails if a private name reaches the output
```

- **Intentional visual changes:** run `npx playwright test --update-snapshots` locally for the macOS baselines. Run the deploy workflow with `update_snapshots: true` for the Linux baselines.
- **Visual review:** `npx tsx scripts/screenshots.ts out` (full pages) and `npx tsx scripts/pdf-to-png.ts out` (PDF pages). Look at the images before calling UI work done.

## Layout

| Path | Purpose |
|---|---|
| `data/resume.yaml` | Resume content (edit this) |
| `data/repos.yaml` | Featured, excluded and masked repos |
| `data/github.json` | Generated stats (weekly CI) |
| `src/lib/data.ts` | Loads and validates all data with zod; formatting helpers |
| `src/pages/index.astro` | Terminal-style profile page |
| `src/pages/print.astro` | Print layout for the PDF |
| `scripts/` | `fetch-github`, `build-pdf`, `leak-check`, `write-build-info`, `update-readme`, screenshot helpers |
| `tests/` | Playwright specs and visual baselines |
| `.github/workflows/` | `ci.yml` (PRs) and `deploy.yml` (main, weekly cron, manual) |
| `.claude/commands/` | Agent workflows: `/update-resume`, `/refresh-projects`, `/tailor` |

## Git

- Branch per change. Use Conventional Commits (`feat:`, `fix:`, `content:`, `chore:`).
- Open a PR with `gh pr create`. CI must be green before merge.
- Commit as the owner's GitHub noreply identity (already set in local git config).
